# Frontend notes

Plain-language guide to the Cash Guard frontend, so anyone on the team can explain any part of it to the judges.
A new section is added after each build phase.

## Where the frontend lives

This repo holds one Replit app with two parts:

| Folder | What it is | Address |
|---|---|---|
| `artifacts/orbyte` | The website people see (our Cash Guard screens). | `/` |
| `artifacts/api-server` | The backend (T1): data, rules, calls to the AI on RunPod. | `/api` |

Both run on the same `.replit.app` link, so the website can reach the backend without any extra setup.

## How to update the live link

GitHub does not push to Replit by itself. After code is pushed to GitHub:

1. In Replit: **Tools → Git → Pull**. The preview restarts with the new code.
2. For the link the judges open: **Tools → Publishing → Publish**.

## The settings

Set in `artifacts/orbyte/.replit-artifact/artifact.toml` under `[services.env]`. They are public (they end up in the web page), never put keys there.

| Setting | What it does | If missing |
|---|---|---|
| `VITE_USE_MOCK` | `true`: use the built-in demo data. `false`: ask the real backend. | Demo data |
| `VITE_API_BASE_URL` | Backend address when demo data is off. Empty means "the same server" (`/api`). | Same server |
| `VITE_DEMO_MODE` | `true`: show the floating Demo button (bottom-right). | Button hidden |

## Is the AI connected? (read this before the demo)

**Not yet.** With `VITE_USE_MOCK = "true"` the website runs on demo data. The AI explanation, the action ranking and the
EN/BM messages are sample texts written in advance (`artifacts/orbyte/src/mocks/fixtures.ts`). The screen says so:
a "Demo data" label in the top bar, "Sample AI text" under the explanation, "Sample draft" next to each message.

What is real today: SEA-LION on RunPod answers through `/api/ai-test` (page `/tes-ai`).

To connect Cash Guard to the real AI:

1. T1 builds the `/api/cash-guard/...` endpoints in `artifacts/api-server` (contract: `docs/frontend-api-contract.md`).
   The AI call can reuse the RunPod code in `artifacts/api-server/src/routes/ai-test.ts`. Numbers stay in normal code;
   the AI only writes the explanation, ranks the 3 action types and drafts the messages, with a rules-based fallback.
2. Set `VITE_USE_MOCK = "false"` in `artifacts/orbyte/.replit-artifact/artifact.toml`, Pull and Publish.
   The labels then switch to "Generated by SEA-LION · RunPod".

## Phase 1: Foundations

**What was built:** colours and fonts, and the rules for showing money and dates. No real screens yet: the page at `/` is a temporary check page. The AI test page (`/tes-ai`) still works.

| File (in `artifacts/orbyte`) | In plain words |
|---|---|
| `src/styles/tokens.css` | The design tokens: every Cash Guard colour, as a variable. |
| `tailwind.config.ts` | Turns the tokens into classes such as `bg-accent`, `text-title`, `rounded-card`. Tailwind's default colours stay available for the older pages. |
| `src/index.css` | Loads the tokens and Tailwind; sets the page background, text colour, Inter font and the focus ring keyboard users see. |
| `src/lib/format.ts` | Turns numbers into `RM 8,400.00` and dates into `25 Oct 2026`. Every screen uses it. |
| `src/lib/format.test.ts` | Automatic checks for `format.ts` (`pnpm --filter @workspace/orbyte run test`). |
| `src/lib/env.ts` | Reads the settings above, in one place. |
| `src/vite-env.d.ts` | Tells TypeScript the names of those settings, so a typo is caught. |
| `src/pages/scaffold-check.tsx` | Temporary check page. Replaced by the Orbyte shell in Phase 2. |
| `CLAUDE.md` | Standing rules for anyone (or any AI) writing code here. |

### Decisions worth knowing

- **We kept the repo's existing tools** (React 19, wouter, Tailwind 3) instead of the ones in the original frontend brief. Swapping them would risk breaking the working Replit setup.
- **The at-risk colour is `#985B00`, not the brief's `#B26B00`.** The brief's colour is too light for small text under WCAG AA (4.2:1, needs 4.5:1). The new one is 5.5:1.
- **Dates are built from a fixed month list**, because browsers now write September as "Sept". This also stops a viewer's time zone from shifting a date by a day.
- **Money uses a true minus sign**, as in the brief: `−RM 8,400.00`.
- **PO-077 fix (agreed with Owen):** in the brief, the RM 1,200 packaging order was never counted as money going out, yet "Hold purchase" claimed to save RM 1,200. From Phase 3 it counts as money out before payday, and the bank balance becomes RM 7,400 instead of RM 6,200, so every headline number in the brief stays the same (−8,400, +1,380, +2,580, +3,400).
- **No lint check yet:** adding a linter would change the shared install file used by the whole team.

## Phases 2–5: Orbyte shell, demo data, Overview, Actions

**What was built:** the clickable core of the demo. Open the site and it goes straight to Cash Guard inside a mock Orbyte workspace.
A judge can see the shortfall, understand why, try actions in "What if", open an action, edit the customer messages (EN/BM),
and approve it as Owner. The numbers update everywhere and the decision is recorded.

### How data flows

```
Screen (e.g. OverviewPage)
  → useApi(getSummary)                 src/lib/useApi.ts   loads data, shows loading/error, reloads after any change
  → client.ts                          src/api/client.ts   the only door to data
      mock mode → mocks/engine.ts      fake backend: the only place numbers are calculated
      real mode → fetch /api/...       T1's backend (same contract)
```

After any change (approve, reject, submit, run check), `client.ts` tells every screen to reload, so the Overview,
the sidebar status and the What-if panel all agree. In mock mode the demo is saved in the browser tab, so a page refresh keeps approvals.

### What each new file does (in `artifacts/orbyte/src`)

| File | In plain words |
|---|---|

| `api/client.ts` | The only place that fetches data. Switches between demo data and the real backend. Sends the "View as" role with every request. |
| `api/errors.ts` | An error with a status code, e.g. 403 when a Finance Admin tries to approve. |
| `mocks/fixtures.ts` | The Kopi Kawan demo data: balances, invoices, bills, the packaging order, AI texts and EN/BM drafts. |
| `mocks/engine.ts` | Fake backend. Projects cash day by day, applies approved actions, checks roles, writes the activity log, handles "AI unavailable". |
| `mocks/engine.test.ts` | 12 automatic checks that the brief's numbers come out exactly (−8,400 / +1,380 / +2,580 / +3,400) and that roles are enforced. |
| `lib/useApi.ts` | Small helper every screen uses to load data. |
| `lib/role.ts`, `layout/RoleProvider.tsx` | Remembers who is "clicking": Owner or Finance Admin. |
| `lib/status.ts` | How Safe / At risk / Shortfall look: always an icon plus words, never colour alone. |
| `layout/OrbyteShell.tsx`, `Sidebar.tsx`, `TopBar.tsx` | The mock Orbyte workspace: menu with live Cash Guard status, company name, credits, "View as" switch, avatar. On phones the menu slides in. |
| `layout/PlaceholderPage.tsx` | Shown for Orbyte modules outside the demo (People, Hiring…) and for tabs not built yet. |
| `components/*` | Shared pieces: Button, Card, Money, StatusPill, AiBadge, Dialog (pop-ups that trap keyboard focus and close with Esc), Skeleton, ErrorState, Toast. |
| `features/cash-guard/CashGuardLayout.tsx` | Cash Guard title and its six tabs. |
| `features/cash-guard/OverviewPage.tsx` and its parts | Status banner, 4 key figures, cash chart (current vs. with actions), "Where the number comes from", AI explanation with its sources, What-if panel, "Run check now" progress steps. |
| `features/cash-guard/ActionsPage.tsx` and its parts | AI-ranked action cards, the side panel (invoices to chase, editable EN/BM messages, bill/order facts), role buttons, the confirm and reject dialogs, success message. |

### Business rules (also in `docs/frontend-api-contract.md`)

- Invoices not yet overdue count in full. Overdue invoices count only once a reminder is approved, weighted by how likely the customer is to pay.
- Approving "Move bill" moves it to its allowed later date; approving "Hold purchase" moves the order to after payday.
- Safe if the balance after payroll is at least the buffer; At risk if between 0 and the buffer; Shortfall if below 0.
- Only the Owner approves, rejects or changes settings; only the Finance Admin submits for approval. Checked in the engine, not just by hiding buttons.
- Salaries are never touched: the AI can only pick from three action types.

## Phases 6–7: the other tabs and the Demo button

| File (in `artifacts/orbyte/src`) | In plain words |
|---|---|
| `features/cash-guard/ReceivablesPage.tsx` | Customer invoices. Filter All / Overdue / Due before payday, sort by days overdue or amount. Overdue rows show an icon and "21 days overdue", not just colour. |
| `features/cash-guard/BillsPage.tsx` | Bills (can each one move, why, penalty) and purchase orders (when paid, urgent or not). |
| `features/cash-guard/ActivityPage.tsx`, `ActivityItem.tsx` | The audit trail, newest first: agent runs, data read, AI output (or fallback), approvals and rejections with who, role, time and reason, demo simulations. People's decisions are highlighted. Each entry opens to show details. |
| `features/cash-guard/SettingsPage.tsx`, `SettingsForm.tsx` | Payday, alert lead time, safety buffer, message language, allowed actions. Locked row: "Never propose delaying or reducing salaries". Only the Owner can save; Finance Admin sees it read-only. |
| `layout/DemoControls.tsx` | Floating "Demo" button (only when `VITE_DEMO_MODE=true`): Run check now, Simulate customers pay, Simulate AI unavailable, Reset demo data. |
| `components/TableHeader.tsx`, `tableStyles.ts` | One table style: a normal table on laptops, stacked cards on phones. |

Also changed: after any change in numbers (approve, customers pay, settings) the explanation is rewritten,
so it never says "shortfall" while the status says "Safe". Activity times never show earlier than the 08:00 daily check.

### Demo story (2 minutes), all checked by clicking through in Chrome

1. Overview: **Shortfall, −RM 8,400.00**, AI explains why. What-if with all 3 actions: **+RM 2,580.00 Safe**.
2. Actions → "Chase 3 overdue invoices" → switch a message to BM → Approve → "3 messages will be queued… Nothing is sent until you confirm" → Confirm.
   Overview now: **RM 1,220.00 short**.
3. View as Finance Admin: no Approve button, only "Submit for approval". Settings are read-only.
4. Demo → Reset. Demo → Simulate customers pay → **At risk, +RM 800**. Approve "Move the Biji Emas bill" → **Safe, +RM 3,400.00**.
5. Demo → Simulate AI unavailable → "Fallback (rules-based)" badge and rules text, no blank areas.
6. Activity Log: every step above, with who, role, time and reason.
